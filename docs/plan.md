# ext4 추가 후보 실험 계획

Linux 5.4.214, 기존 전용 Ubuntu VM. 이전 HTree 실험에서 효과가 없었던 노드 내부 탐색은 변경하지 않는다. HTree 실험 패치의 binary 모드를 공통 기준으로 고정하고 신규 후보는 독립적으로 켠다. 동일 커널 안 mode0/1 비교이며 완전 무수정 커널 비교와 구분한다.

## 사전 선정

1. 디렉터리 이름 비교: 길이가 같고 8바이트 이상인 일반 파일 이름은 뒤 8바이트부터 비교해 불일치 후보를 제거하고, 일치하면 기존 전체 비교를 수행한다. casefold와 암호화 경로는 기존 동작을 유지한다. 길고 공통 접두사가 있는 이름/짧은 이름/무작위 이름과 dcache 상태를 비교한다. 이름 내용에 따라 이득이 달라질 수 있으므로 특정 패턴 결과를 일반화하지 않는다.
2. extent status의 최근 조회 캐시: ES tree에서 찾은 extent를 최근 포인터에 갱신한다. upstream의 READ_ONCE/WRITE_ONCE 경쟁 보정을 공통 적용한 뒤 정책만 비교한다. 반복 지역성/순차/무작위 접근, SEEK_DATA/HOLE 정답을 검사하고 실제 함수 진입·포인터 적중·트리 비교 횟수를 별도로 계측한다. 시스템 호출 측정과 일반 파일 읽기 성능을 구분한다.
3. inline_data: 기존 ext4 기능을 켜고 끈 파일시스템에서 작은 파일 생성·읽기·확장을 비교한다. 직접 만든 커널 개선이 아니라 저장 방식 선택의 효과를 보는 대조 실험이다. 데이터 내용, 실제 inode 플래그와 블록 사용량, 확장 시 변환 비용을 검증한다.

## 측정 원칙

- 벤치마크·기록·이미지는 새 실험 디렉터리만 사용한다. 수업 데이터와 기존 결과는 보존한다.
- 각 조건 순서를 섞고 같은 round 비율의 중앙값·범위·개선 회수를 보고한다. 동일 baseline을 반복하는 shadow 조건으로 잡음을 확인한다.
- 시간 측정은 커널 계측을 끈다. 경로 진입과 구조적 비용 계측은 별도 실행한다.
- 캐시 상태와 CPU 고정 여부를 기록한다. VM의 물리 디스크 캐시를 통제했다고 주장하지 않는다.
- 파일 내용/반환값 불일치, 커널 경고, fsck 오류는 성능 결론보다 먼저 처리한다.
- 뚜렷한 개선 후보는 별도 seed 또는 별도 부팅으로 재확인한다. 개선이 없거나 손해인 조건도 보존한다.
- 완료 후 실험 이미지를 분리하고 원래 커널로 복귀한다.
